# GPTAdmin: подключение внешнего агента

Прочитай эту инструкцию целиком. Профиль доступа: `{{PROFILE_ID}}`. Доступ действует до **{{EXPIRES_AT}}**. Используется MCP `{{PROTOCOL}}` поверх JSON-RPC 2.0 и Streamable HTTP.

Ссылка и скачанный конфиг дают временный доступ. Храни их только в своей песочнице, не добавляй в Git, сообщения другим людям, логи или опубликованные документы. Отзыв ссылки и истечение срока прекращают также доступ скачанного клиента. Заголовок no-store управляет HTTP-кэшами, но не удаляет уже скопированный текст из внешней платформы.

## 1. Скачай готовый клиент

Нужен Python 3 со стандартной библиотекой. Не пиши собственный MCP-транспорт.

```bash
curl --fail --silent --show-error --config - <<'GPTADMIN_CLIENT'
url = "{{BOOTSTRAP_URL}}/client.py"
output = "gptadmin.py"
GPTADMIN_CLIENT
python3 gptadmin.py bootstrap - <<'GPTADMIN_BOOTSTRAP'
{{BOOTSTRAP_URL}}
GPTADMIN_BOOTSTRAP
python3 gptadmin.py --help
```

Клиент сохраняет отдельный конфиг с правами 0600. Он умеет современный MCP, JSON и SSE, structuredContent, задания, большие ответы и бинарную передачу файлов с проверкой SHA-256. Токен передаётся в Authorization, не в адресе MCP. Схемы конкретных инструментов всегда получай с сервера.

## 2. Определи проект и проверь координацию

После установки используй встроенные команды клиента: `python3 gptadmin.py discover` показывает реальные доступные хосты и MCP-серверы, а `python3 gptadmin.py search "find_paths"` позволяет найти доступный инструмент поиска файлов и проектов. Для точных аргументов используй `schema`. Доверяй только инструментам, реально найденным в своём профиле доступа.

По задаче пользователя установи проект, фактический хост и канонический репозиторий. Если местоположение неизвестно, ищи через доступный GrepMesh (например, `find_paths` и `search`), а при его отсутствии — штатными разрешёнными средствами просмотра каталогов и поиска. Не придумывай пути и названия MCP-инструментов. Отсутствие дополнительного поискового инструмента само по себе **не блокирует** работу.

Для координации найди Agent Herder через `search`. Если доступен, прочитай схемы `workspace` и `coordination_note`, проверь текущих владельцев и конфликты и зарегистрируй область работы до редактирования. Используй настоящий ID сессии; если песочница его не раскрывает, прямо укажи это. Если Agent Herder недоступен, зафиксируй ограничение и продолжай разрешённый независимый поиск и чтение. Не начинай конфликтующую запись без проверки владения рабочей областью и не присваивай чужую сессию.

Для инженерной задачи сразу следуй **Last Human Commit** ниже. Прочитай проектный AGENTS.md, найди канонический репозиторий и создай отдельный Git worktree и ветку. Не редактируй общий main. Для длинной задачи веди штатный LHC-план, выполняй разрешённую работу до проверенного результата и используй существующий процесс review, merge и release. Повторное разрешение уже порученной работы не требуется; реальные ограничения доступа и человеческий STOP обязательны.

## 3. Работай через готовые инструменты

Для каталога используй search, для точных аргументов schema, для вызова call или exec. В exec запускай независимые вызовы вместе и возвращай только нужный результат. Готовый shell-путь передаёт argv и stdin без вложенных shell-кавычек. Для файлов используй upload/download, а не cat, ручной base64 или terminal output. Файловые операции сохраняют байты и проверяют SHA-256.

Если ответ содержит job_id, taskId, operation_id или continuation, проверяй существующую операцию и читай продолжение. После тайм-аута не повторяй автоматически запись, запуск или отправку. Успешный HTTP-код не отменяет isError и не доказывает исполнение. Не считай усечённый вывод полным. При `instructions_required` с `executed:false` перечитай актуальные инструкции перед разрешённым новым вызовом.
