# Внешние агенты: подключение одной ссылкой

Временная ссылка выдаёт инструкции выбранного профиля, полный Last Human
Commit и готовый клиент Python. Клиент использует MCP `2026-07-28` поверх
JSON-RPC 2.0 и Streamable HTTP. Установка дополнительных пакетов не нужна.

## Создание в консоли

1. Откройте **Доступ → Внешние агенты** (`/admin/#bootstrap`).
2. Задайте название и явно выберите профиль доступа.
3. Оставьте срок **7 дней** либо выберите другой целый срок от 1 до 3650 дней.
4. Нажмите **Создать ссылку**, затем **Копировать сообщение**.
5. Вставьте сообщение в чат внешнего агента и допишите задачу.

Секретная ссылка показывается только после создания. В списке остаются
название, профиль, срок и состояние. Если ответ на создание потерялся,
сначала обновите список и проверьте результат. Не повторяйте создание вслепую.

Кнопка **Отозвать** отключает ссылку и выданный ей MCP-ключ. То же происходит
при истечении срока. Уже принятые сервером операции не отменяются задним числом.
Изменения прав профиля применяются при последующих вызовах; удалённый профиль
не позволяет продолжить подключение.

## Что получает агент

- Полную инструкцию с проверенным источником и SHA-256 Last Human Commit.
- Текущие инструкции своего профиля, без копирования конфигурации другого клиента.
- Порядок работы: через `discover` и `search` найти реальные доступные
  средства обнаружения проекта (GrepMesh/`find_paths`, если присутствуют),
  определить фактический хост и репозиторий, зарегистрировать область
  работы в Agent Herder при наличии доступа, затем выполнить LHC.
- `gptadmin.py`: поиск, схемы, вызовы, shell с argv/stdin, чтение заданий и
  больших результатов, загрузка и скачивание файлов с SHA-256.
- Конфигурацию с отдельным ограниченным по сроку ключом, сохраняемую с правами 0600.

Нет обязательной зависимости от отдельного Entity Finder: этого инструмента
нет в стандартном каталоге GPT Admin. Отсутствие дополнительных поисковых
или координационных MCP-инструментов не препятствует разрешённому чтению и
независимой работе. Имена инструментов и пути не угадываются; при риске
конфликтующей записи сначала проверь владение рабочей областью.

Файлы передаются штатным `file_transfer`: до 16 MiB за одну передачу,
блоками до 32768 байт. Загрузка создаёт новый файл без перезаписи существующего.
Подробные команды находятся в [EXTERNAL_BOOTSTRAP_CLIENT.md](EXTERNAL_BOOTSTRAP_CLIENT.md).

## Настройка источника Last Human Commit

Перед выдачей ссылок задайте переменную окружения процесса Hub/Node:

```text
GPTADMIN_BOOTSTRAP_LHC_PATH=/home/admin/.codex/plugins/cache/megamen32-plugins/last-human-commit
```

Рекомендуется абсолютный путь к **каталогу установленных версий** LHC.
Прежние пути вида `…/<версия>` и `…/<версия>/AGENTS.md` указывают на этот же
каталог версий, даже если обновление уже удалило указанную версию. Явный
путь к файлу вне каталога версии или ссылка `active` закрепляют источник.

Для точной раскладки Codex `<CODEX_HOME>/plugins/cache/<market>/last-human-commit`
второй источник — локальный checkout того же marketplace:
`/home/admin/.codex/.tmp/marketplaces/megamen32-plugins/plugins/last-human-commit`
в конфигурации выше. Bootstrap при каждом запросе выбирает наибольшую полную
доступную версию `major.minor.patch`, сравнивая числа. При равной версии
используется runtime cache. Файл `AGENTS.md` в корне каталога версий
игнорируется. Если новый пакет ещё распаковывается, выдаётся доступный полный
пакет. Hub не обращается к сети и не копирует файлы.

В парной раскладке нужны два обычных файла в одном пакете: непустой UTF-8
`AGENTS.md` до 256 KiB и `.codex-plugin/plugin.json` до 64 KiB. Манифест
задаёт имя `last-human-commit` и версию; в runtime cache версия должна
совпадать с именем каталога. `manifest.json` в Bootstrap сообщает путь,
версию и SHA-256 прочитанного документа; `common/` относится к этому пакету.

Для обычного каталога версий вне этой раскладки проверяется только самая
новая версия. Если в парной раскладке нет ни одного полного пакета или
закреплённый либо выбранный одиночный источник недоступен, Bootstrap
возвращает 503 при создании ссылки и скачивании любого ресурса. Новый ключ
при этом не выдаётся.

## HTTP-контракт и права

| Запрос | Результат |
| --- | --- |
| `GET /admin/api/bootstrap-links` | Метаданные выданных подключений без секретов |
| `POST /admin/api/bootstrap-links` | Новая ссылка, готовое сообщение и метаданные |
| `DELETE /admin/api/bootstrap-links/{id}` | Отзыв ссылки и соответствующего ключа |
| `GET /bootstrap/{capability}` | Полная Markdown-инструкция |
| `GET /bootstrap/{capability}/client.py` | Готовый клиент без встроенного ключа |
| `GET /bootstrap/{capability}/config.json` | Конфигурация и временный ключ |
| `GET /bootstrap/{capability}/manifest.json` | Версия протокола, SHA-256 клиента и LHC |

POST принимает `label`, обязательный `profile_id` и необязательный `ttl_days`.
Без `ttl_days` используется 7 дней. Управление требует роли администратора
и соответствующего действия `access_clients`: `list`, `issue` или `revoke`.
Сам внешний ключ всегда получает роль `client` и права выбранного профиля.
Доступ на просмотр списка не даёт право выдавать или отзывать подключения.

Capability содержит случайный секрет из 32 байт. В приватном хранилище
сохраняется его SHA-256; исходную ссылку сервер повторно не восстанавливает.
Ссылка и MCP-ключ используют одну существующую запись доступа, один срок
и один механизм отзыва. Неверная ссылка возвращает 404, истёкшая или
отозванная возвращает 410. Скачанный ключ после отзыва не проходит MCP-аутентификацию.

## Кеширование и журналы

Ответы подключения содержат `Cache-Control: no-store, private, max-age=0`,
`Referrer-Policy: no-referrer` и запрет индексации. Приложение скрывает
capability в ingress/audit-журналах. Штатный nginx-шаблон не записывает
запросы `/bootstrap/` в access/error logs. При отдельном reverse proxy
примените аналогичное правило и запрет кеширования до выдачи первых ссылок.

Ссылка является доступом в пределах профиля. Не помещайте её, конфигурацию
или содержимое полного workflow в публичные репозитории и отчёты.
`no-store` управляет HTTP-кешами и не удаляет текст, который внешняя платформа
уже получила и сохранила в истории чата.
