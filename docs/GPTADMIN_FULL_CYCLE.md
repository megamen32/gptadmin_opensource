# GPTAdmin: восстановление и полный цикл

Приоритет владельца от 7 ноября 2026: сначала работающий GPTAdmin и доступ к
Herder, затем уменьшение стоимости обычного MCP-сценария. Каждый баг проходит
RED → минимальное исправление → тот же GREEN → реальный клиентский путь.

Go остаётся языком backend GPTAdmin. Новые самостоятельные проекты — Rust.
Предпочитать чистые преобразования данных с явными побочными эффектами.
Существующий установщик не переписывать во время восстановления сервиса;
не добавлять новые Python-сервисы или второй журнал задач.

## Результат исследования

Airlock run_js объединяет inspect, вызовы и tasks в одном скрипте. Его текущий
stateless MCP не поддерживает фоновые подписки: наблюдение задач идёт через
get/list. Большое описание инструмента само по себе не экономит токены.

OpenCode V2 execute объединяет MCP-вызовы и обрабатывает промежуточные результаты
вне контекста модели. Вложенные вызовы сохраняют свои проверки прав.
Официальные источники: https://opencode.ai/docs/migrate-v1/,
https://opencode.ai/docs/tools/#execute, https://opencode.ai/docs/mcp-servers/.

GPTAdmin уже имеет JS sandbox, typed tools, schema validation и durable Tasks.
Нужно использовать эту основу. mcp.schema сейчас получает весь каталог target,
после чего preflight выбирает нужный инструмент. Первый функциональный шаг —
точечный inspect одного инструмента с версией схемы и проверкой доступа.

## Этапы исполнения

1. Снять baseline одного и того же реального сценария на Codex и OpenCode:
   discovery → inspect/schema → exec → result. Считать все входные/выходные
   токены, количество обращений, задержку, CPU/RAM и ошибки.
2. Добавить точечный inspect внутри текущего исполнителя. Тест сначала
   доказывает отсутствие лишнего каталога и сохранность границ доступа.
   Старые имена/форматы сохраняют адаптеры совместимости.
3. Проверить долгую задачу независимо от жизни JS: start → get/result,
   cancel, expiry в 3 часа, рестарт. Использовать существующий ledger,
   не повторять операции с неизвестным результатом. Подписки добавлять
   только для реализованного и проверенного протокольного сценария.
4. Проверить устойчивую identity узла при смене hostname, обновление схемы,
   отключение/возвращение дочернего MCP и обычный путь Herder.
5. Измерить параллельность на узле с 1 ГиБ RAM и на основном Hub.
   Большие результаты читать выборочно, без двойной выдачи structuredContent
   и text. Не объявлять бюджет памяти доказанным по одной константе.
6. Пройти modern/legacy сценарии реальными клиентами, review итогового diff,
   полный применимый GREEN, публикацию и установку одной ревизии,
   независимую проверку клиента и проверку обратного перехода.

Каждый этап заканчивается отдельной доставкой работающего результата.
Критерий экономии: тот же полезный ответ с меньшими суммарными токенами,
без увеличения ошибок, потери прав, результатов или истории. Процент экономии
и предельная нагрузка заранее не заявляются; они выводятся из baseline.
