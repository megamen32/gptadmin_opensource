# ToDo через GPTAdmin

Подключена существующая доска `https://todo.bezrabotnyi.com/`, а не новый
сервер или хранилище. Проект GPTAdmin:
`https://todo.bezrabotnyi.com/?project=GPTAdmin&view=all`.

Обычный MCP-клиент находит инструменты запросом `search("kanban")`.
Нужно использовать target из результата поиска, затем `kanban.project.list`,
`kanban.list` с `project: "GPTAdmin"` и `paged: true`, `kanban.read` и
`kanban.change`. Изменение карточки требует свежий `expectedVersion`.
Не искать доску сканированием файлов сервера. Неполная загрузка посторонних
дочерних MCP не означает, что инструменты ToDo недоступны.

На Node100 используется обычное общее операционное MCP-подключение `Todo`.
Доступ продолжает проверяться профилем GPTAdmin и нативной авторизацией доски.
Фильтр проекта не является отдельным ACL на данные доски. Персональное
подключение через `owner_profile_id` требует отдельного managed HTTP connection
и не совместимо с обычным `mcp.call` фасадом; оно здесь не используется.

Новый ChatGPT OAuth-клиент получил именованный профиль с прежними unrestricted
target/tool правилами; роль клиента не повышалась. Служебный токен доски
создан штатным AuthStore, хранится только в защищённой конфигурации Node.
Его текущий срок — 30 дней с 8 ноября 2026; автоматическое продление этим
изменением не реализовано. До истечения нужен штатный перевыпуск и upsert
одного подключения. Не копировать токен в документацию или Git.

Приёмка 8 ноября: отдельный обычный MCP credential с тем же профилем ChatGPT
прошёл публичный endpoint, нашёл проект, создал карточку и изменил её с CAS;
повторное чтение подтвердило версию 2. Это проверка MCP-пути и профиля,
не утверждение о выполнении нового хода в интерфейсе ChatGPT.

Исправление 1111 возвращает встроенные control-схемы сразу, с фильтрацией
исходного caller/target. Оно не ставит `control:*` в очередь relay-процесса,
которого у виртуальной поверхности нет. Старые задания не повторяются.
