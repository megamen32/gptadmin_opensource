## Запросить корреляцию

Хаб принимает необязательный заголовок запроса W3C `traceparent`. Он возвращает
проверенный дочерний элемент `traceparent` и ограниченный заголовок ответа `X-Request-ID`;
задания ретрансляции в очереди и задания ShellMCP переносят одни и те же поля корреляции через опрос
и выдача результата. Недопустимые заголовки трассировки отбрасываются и заменяются. След
метаданные никогда не содержат аргументы команды, учетные данные или содержимое файла.

Оператор может выбрать экспорт журналов OTLP/HTTP с помощью
`GPTADMIN_OTLP_ENDPOINT`. Внешние сборщики должны использовать HTTPS; обычный HTTP
принимается только для сборщиков обратной разработки. Экспортер использует
ограниченная асинхронная очередь и экспортирует поля событий из разрешенного списка, такие как
политическое решение, инструмент, ссылка на результат и идентификаторы трассировки. Он никогда не экспортирует сырье
аргументы, команды, учетные данные, URL-адреса или содержимое файла и сборщик
сбои доставки не приводят к сбою исходного запроса концентратора.

## Удаленный секретный доступ

Клиенты MCP с полным доступом могут вызывать `secret_request` и `secret_status`.
first возвращает только `request_id`, `input_url`, `secret_ref`, `env_name`, `file`
и метаданные об истечении срока действия. Оператор передает значение один раз в
`POST /secret-input/{token}`; ни MCP, ни орган реагирования не принимают и не
возвращает открытый текст. Более поздний `shell_exec` может пройти
`secret_env: {"ENV_NAME": "secret_ref"}`. Ответы на задания Hub и журналы удаляются.
разрешенное значение, и профили только для чтения не могут получить доступ к этим операциям.

## Текущие API для доступа и инвентаря (контракт исходного кода)

Эти маршруты требуют авторизованный административный запрос (`CTL_TOKEN`,
сессию администратора или допустимый существующий MCP bearer — в зависимости
от middleware маршрута). Для вызова из браузерной сессии обработчики выборки
ресурсов и изменения proxy-route также проверяют same-origin. Ниже описан
контракт текущего исходного кода; установка и проверка работающего экземпляра
подтверждаются отдельно.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/admin/api/overview` | Сводка Hub, включая текущий инвентарь узлов и недавние задания. |
| `GET` | `/admin/api/clients` | Безопасный инвентарь подключений; используйте его вместо маршрута, раскрывающего сохранённый токен. |
| `GET` | `/admin/api/access-profiles` | Список профилей доступа. |
| `GET` | `/admin/api/access-profiles/{id}` | Получить профиль и его `ETag`. |
| `PUT` | `/admin/api/access-profiles/{id}` | Создать с `If-Match: *` или заменить с текущим `ETag` в `If-Match`; устаревшая версия отклоняется. |
| `POST` | `/admin/api/mcp/issue-token` | Выпустить MCP bearer по `client_id`, необязательным `profile_id`, `role`, `ttl_days` и `access_mode`. Режим: `full` или `readonly` (по умолчанию `full`); `ttl_days: 0` выбирает срок по умолчанию на сервере. Ответ один раз содержит секретный `access_token`. |
| `POST` | `/admin/api/servers/resources` | Запросить текущий снимок ресурсов у точного узла `shell:<id>`. |
| `GET` | `/admin/api/jobs?server_id=shell:<id>&limit=1` | Получить последнее сохранённое задание ровно этого shell-узла: фильтрация по точному ID выполняется до сортировки и лимита. История доступна и при отключённом узле. |
| `GET` / `PUT` | `/admin/api/proxy-route` | Прочитать или сохранить фиксированный профиль proxy-route VUSA → node-44. |
| `POST` | `/admin/api/proxy-route/{enable,disable,reconcile,probe}` | Управлять этим фиксированным маршрутом или проверять его. |

В инвентаре overview могут присутствовать сам Hub (`hub`), реальные дочерние
MCP (`real_mcp`), удалённые ShellMCP-узлы (`virtual_shell`), внутренние
виртуальные MCP (`virtual_mcp`) и парные файловые/управляющие поверхности
(`virtual_file`, `virtual_control`). Парные поверхности ссылаются на основной
узел и не являются отдельными хостами.

Тело запроса ресурсов: `{"server_id":"shell:<точный-id>"}`. Завершённый
снимок содержит `sampled_at` (UTC RFC3339), общий `status` (`available`,
`partial` или `unavailable`) и компоненты `cpu`, `memory`, `root_filesystem`
со своими статусами. CPU — измеренная загрузка за короткий интервал, а не
средняя загрузка системы. Память содержит общий, использованный и доступный объём в
байтах; корневая файловая система — общий, использованный и доступный
пользователю свободный объём. При долгом запросе может вернуться
`status: "pending"` и `job_id`. Для отключённого или неизвестного узла, а также
при ошибке или неверном формате запроса, возвращается `unavailable`, причина и
`sampled_at: null`. Завершённый снимок содержит реальное время измерения даже,
если все компоненты недоступны. Ошибка компонента не подменяется нулём; при
частичном снимке недоступные проверки остаются явно помечены.

Маршрут заданий возвращает реально записанные Hub метаданные задачи и краткий
фрагмент результата/ошибки для этого узла. Это история Hub; сам запрос истории
не означает, что узел недавно ответил или сейчас в сети.

Профиль proxy-route ограничен исходным кодом: потребитель VUSA, DE HTTP выход
через node-44, loopback listener `127.0.0.1:24836` и существующая ссылка на
SSH-идентичность `ssh-config:relay02`. `GET` отдельно показывает сохранённый
профиль и состояние службы, listener и последней проверки. По умолчанию
желаемое состояние — disabled; контракт API не утверждает, что маршрут включён
или работает.

См. [Конфигурация → Модель аутентификации](./CONFIGURATION.md#auth-model).

## API администратора (`/admin/api/*`)

Аутентификация носителя с помощью `CTL_TOKEN`. Только сведения о переносе устаревшей административной панели/веб-панели.

### `GET /servers`

Список зарегистрированных агентов Shellmcp.

```json
{
  "servers": [
    { "name": "node-01", "url": "http://203.0.113.10:25901", "alive": true, "last_seen": "2026-06-29T10:00:00Z" }
  ]
}
```

### `POST /exec`

Выполните команду оболочки на целевом агенте.

```json
{
  "server": "node-01",
  "cmd": "systemctl status nginx"
}
```

Ответ (если длинный, сокращен для экономии токенов):

```json
{
  "stdout": "● nginx.service - The nginx HTTP server...",
  "stderr": "",
  "exit_code": 0,
  "truncated": false
}
```

### `GET /tasks/{task_id}`

Получите статус фоновой задачи.

### `POST /file/backup`

Перед редактированием создайте управляемую резервную копию файла.

### `GET /system/info?server=node-01`

ЦП, ОЗУ, диск, время безотказной работы целевого агента.

Устаревшая схема импорта: `https://became.bezrabotnyi.com/api.json` или
`https://became.bezrabotnyi.com/openapi.yaml`. Использование пользовательского импорта GPT
`/actions/openapi.yaml` или `/server/{slug}/actions/openapi.yaml`, а не эти
устаревшие псевдонимы.

## Конечная точка MCP (`/mcp`)

Аутентификация носителя OAuth. Удаленный SSE MCP (Streamable HTTP).

Сюда подключаются клиенты MCP (Claude Desktop, Codex, OpenCode). Концентратор предоставляет
инструменты Shellmcp как инструменты MCP:- `shell_exec` — запустить команду оболочки
- `file_read` — прочитать файл
- `file_write` — записать файл (с резервной копией)
- `file_backup` — создать управляемую резервную копию.
- `systemd_status` / `systemd_start` / `systemd_stop` / `systemd_restart`
- `system_info` — ЦП/ОЗУ/диск/время безотказной работы
- `system_health` — быстрая проверка работоспособности
- `dir` — указать каталог

См. настройку [Адаптеры → MCP client](./ADAPTERS.md#1-mcp-client)].

## Схема OpenAPI

– Канонический импорт пользовательского GPT: `GET /actions/openapi.yaml`.
- Импорт для каждого сервера: `GET /server/{slug}/actions/openapi.yaml`
- Старые псевдонимы: `GET /api.json` и `GET /openapi.yaml`.

Канонические URL-адреса импорта являются общедоступными (без аутентификации). Устаревшие псевдонимы остаются общедоступными.
для миграции, но они не являются пользовательским путем GPT.

## Фоновые задачи

Длительные команды возвращают `task_id` вместо блокировки:

```json
{ "task_id": "abc123", "status": "running" }
```

Опрос с `GET /tasks/abc123` до `status: completed`. ИИ делает это
автоматически.

## Усечение вывода

Длинный stdout/stderr разбивается на части. Ответ включает в себя:

```json
{
  "stdout": "...first 1MB...",
  "truncated": true,
  "spilled_path": "/tmp/spilled.stdout",
  "preview_head": "...",
  "preview_tail": "..."
}
```

ИИ может прочитать дополнительную информацию по запросу посредством последующего звонка. Это экономит токены —
ИИ читает только то, что ему нужно ответить.


## MCP для каждого сервера и прокси-сервер действий OpenAPI

GPTAdmin предоставляет доступ к каждому зарегистрированному серверу MCP через аутентифицированные маршруты для каждого сервера. Замените `{slug}` на `meta.public_mcp_slug` из `GET /mcp-relay/servers`.

| Метод | Путь | Цель |
|--------|------|---------|
| `GET` / `POST` | `/server/{slug}/mcp` | MCP-совместимая конечная точка для одного сервера |
| `GET` | `/server/{slug}/card` | Карта обнаружения сервера |
| `GET` | `/server/{slug}/health` | Состояние сервера |
| `GET` | `/server/{slug}/actions/openapi.yaml` | Сгенерированная схема OpenAPI для пользовательских действий GPT |
| `GET` | `/server/{slug}/actions/openapi.json` | Та же схема, что и JSON |
| `POST` | `/server/{slug}/actions/tools/{tool_name}` | Проксирование вызова действия OpenAPI для одного инструмента MCP |

## Дополнительное виртуальное управление MCP

`network-proxy` и `webhooks` по умолчанию отключены. По умолчанию `/actions/openapi.yaml` остается только ретрансляционным и исключает оба.

| Метод | Путь | Цель |
|--------|------|---------|
| `GET` | `/admin/api/virtual-mcps` | Проверьте оба состояния за один вызов. |
| `PUT` | `/admin/api/virtual-mcps/{id}` | Сохраните `{"enabled": true|false}` для `network-proxy` или `webhooks`. |

`network-proxy` предоставляет ограниченные инструменты сетевого туннелирования: `network_proxy_request`, `network_proxy_approve`, `network_proxy_issue`, `network_proxy_open`, `network_proxy_status`, `network_proxy_revoke`.`webhooks` предоставляет незасекреченный маршрут веб-перехватчика CRUD и поиск заданий: `webhook_routes_list`, `webhook_route_create`, `webhook_route_replace`, `webhook_route_delete`, `webhook_job_get`.

Проверка включения: `GET /mcp-relay/servers` показывает только включенные виртуальные MCP.

Используйте после включения: `/server/{slug}/mcp` и `/server/{slug}/actions/openapi.yaml`.

```json
{
  "server_id": "OpenMemory",
  "tool_name": "openmemory_query",
  "status": "completed",
  "response": {"content": []}
}
```

Примеры см. в [MCP Proxy Relay](./MCP_PROXY_RELAY.md)].
