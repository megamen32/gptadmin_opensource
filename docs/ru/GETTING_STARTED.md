# Начало работы

Установите GPT‑Админ, подключите свой ИИ, запустите первую команду — через несколько минут.

## 1. Установите хаб

На машине, на которой будет работать хаб (ваш ПК, VPS или сервер):

```bash
# Linux / macOS — auto-detects user/system mode
curl -s https://became.bezrabotnyi.com/install.sh | bash
```

```powershell
# Windows (PowerShell, no Administrator needed)
iwr -UseBasicParsing https://became.bezrabotnyi.com/install_win.ps1 | iex
```

Установщик создает Хаб, при необходимости запускает Туннель и распечатывает его.
**URL-адрес хаба**. Сохраните этот URL-адрес: это место, откуда вы будете подключаться.

> Домен не требуется: выберите вариант автоматического туннелирования (FRP или Cloudflare), и вы
> получить общедоступный URL. См. [Туннели](./TUNNELS_DOCS.md).

## 2. Установите агент на целевой компьютер

На каждом сервере, которым вы хотите управлять:

```bash
curl -s https://became.bezrabotnyi.com/install.sh | bash
```

При появлении запроса выберите «Только агент». Агент автоматически регистрируется в вашем хабе.

## 3. Подключите свой ИИ

Если клиент уже говорит на MCP, зарегистрируйте хаб один раз:

```bash
gptadmin connect-mcp
```

Для других клиентов выберите адаптер:

- **Claude Desktop/другие клиенты MCP** → [Настройка клиента MCP](./ADAPTERS.md#1-mcp-client)
- **DeepSeek / Qwen / Alice / GigaChat** (бесплатные веб-чаты) → [Расширение для браузера](./ADAPTERS.md#2-browser-extension)
- **Пользовательский GPT ChatGPT / Открытый веб-интерфейс** → [Действие OpenAI](./ADAPTERS.md#3-openai-action)

## 4. Запустите свою первую команду

Спросите свой ИИ простым языком:

- «показать статус nginx на сервере-01»
- «поставить докер на vps-prod»
- «Почему открытая камера отдаёт 503? посмотри логи»
- «запусти кодекс, чтобы исправить ошибку в этом репо»

ИИ вызывает хаб, хаб направляется к агенту, агент выполняет команду
и возвращает реальный выпуск. ИИ читает его и сообщает.

Если вы подключаете пользовательский GPT, импортируйте URL-адрес сгенерированной схемы из
Раздел «Действия» в [Адаптеры](./ADAPTERS.md#3-openai-action), затем выберите
Носитель или OAuth там. Никогда не вставляйте внутренние секреты службы в GPT.

## Показать URL-адреса подключения

После настройки распечатайте текущий URL-адрес общедоступного концентратора, режим туннеля, конечные точки MCP и схемы пользовательских действий GPT:

```bash
sudo gptadmin urls
```

Полезные варианты:

```bash
sudo gptadmin urls --all   # include every registered MCP server
sudo gptadmin urls --json  # machine-readable output
```

## Устранение неполадок

**Агент не отображается в `/admin`**
- Убедитесь, что `HUB_URL` установлен и доступен агенту.
- Повторно запустите шаг подключения агента со страницы подключения к хабу.
- Посмотрите журналы агента: `journalctl --user -u shellmcp -n 50`

**`/mcp` возвращает 401**
- Завершите соединение OAuth с URL-адреса концентратора; `/mcp` принимает MCP с ограниченной областью действия
  соединения, а не скопированные учетные данные службы. См. [Конфигурация → OAuth](./CONFIGURATION.md#oauth).
- Если это подключение предшествует поддержке обновления Hub, подключитесь повторно, чтобы получить
  `offline_access` обновить учетные данные. Существующие сеансы не могут получить один
  задним числом.

**Кнопки расширений браузера не отображаются**
- Обновить страницу
- Убедитесь, что в Tampermonkey/Userscripts включен сценарий.
- На некоторых сайтах не работает автоматическая вставка — подсказка находится в буфере обмена, вставьте вручную.

**Проверка пользовательского действия GPT не удалась**
– Убедитесь, что URL-адрес хаба в `servers.url` соответствует вашему хабу.
- Снова откройте страницу подключения к хабу и завершите авторизацию OAuth для
  Пользовательский клиент GPT
