# Безопасность

GPT‑Админ предоставляет агентам ИИ доступ к вашим серверам. Безопасность является главным приоритетом.

## Модель аутентификации (сводка)

GPT‑Админ имеет три механизма аутентификации — см. [Конфигурация → Модель аутентификации](./CONFIGURATION.md#auth-model).
подробности:

1. **`CTL_TOKEN`** (только носитель, устаревшая миграция) — существующий API администратора + установка веб-панели; не используйте его для новой пользовательской настройки GPT.
2. **Носитель OAuth** — конечная точка `/mcp` (для клиентов MCP) и поток схемы пользовательской ретрансляции GPT.
3. **`ADMIN_PASSWORD`** — форма `/oauth/authorize` внутри потока OAuth.

Плюс `SHELLMCP_TOKEN` для регистрации агента → хаба.

## Наименьшие привилегии

- **Пользовательский режим по умолчанию** — агент запускается от имени устанавливающего пользователя, а не от имени пользователя root.
  Системный режим (sudo) можно использовать только тогда, когда вам нужны привилегированные операции.
- **Список разрешенных команд** — ограничить команды, которые агент будет выполнять.
  (настроить в `~/.config/gptadmin/allowlist.txt`).
- **Список разрешенных IP-адресов** — укажите, какие IP-адреса могут достигать агента.

## Обработка секретов

- Секреты **маскируются в журналах** — токены, пароли, ключи API редактируются.

- **Режим «Только локальный»** — для команд с конфиденциальными данными агент может быть
  настроен так, чтобы не возвращать выходные данные в концентратор (запускаться локально, сообщать только о состоянии).

### Администратор МИД

Заблокированное администрирование принимает зарегистрированные учетные данные WebAuthn/пароль или
запасной вариант TOTP. Церемонии WebAuthn представлены по адресу
`/admin/api/security/mfa/webauthn/register/{begin,finish}` и
`/admin/api/security/mfa/webauthn/login/{begin,finish}`; Hub хранит общедоступные
записи учетных данных в `webauthn_state.json` с режимом `0600` и использует
недолговечный файл cookie HttpOnly после подтвержденного входа в систему. OIDC с идентификацией личности
интеграция прокси остается специфичной для развертывания и не подразумевается локальными
регистрация по паролю.

### Удаленный секретный доступ

Удаленные клиенты MCP используют `secret_request` для создания одноразовой записи браузера.
flow и `secret_status` только для чтения метаданных. Значения никогда не должны отправляться
MCP JSON, журналы, записи аудита, проверки заданий или отзывы общественности. Управляемый
`shell_exec` может получить непрозрачное сопоставление `secret_env`; Хаб решает это
на стороне сервера и снова редактирует значение на каждой границе ответа.

Безопасные настройки по умолчанию:

| Переменная | По умолчанию | Контракт |
|----------|---------|----------|
| `GPTADMIN_SECRET_STORE_DIR` | `$GPTADMIN_CONFIG_DIR/secrets` | Режим каталога `0700`; содержит только зашифрованные записи |
| `GPTADMIN_SECRET_STORE_KEY_FILE` | `$GPTADMIN_CONFIG_DIR/secret-store.key` | Режим ключа AES-256 `0600`; отсутствующий/неверный ключ не закрывается |
| `GPTADMIN_SECRET_INGRESS_STATE_FILE` | `$GPTADMIN_CONFIG_DIR/secrets/requests.json` | Запросить режим метаданных `0600`; только хэши токенов |
| `GPTADMIN_SECRET_INGRESS_TTL` | `900` секунд | Ограничено 60–3600 секундами; запросы одноразовые |

Создайте резервную копию ключа и зашифрованного хранилища, используя существующую защищенную
процедура резервного копирования. Если ключ утерян или недействителен, восстановите его из защищенного хранилища.
резервное копирование или воссоздание запроса; GPTAdmin никогда не возвращается к открытым текстовым файлам.
или переменные среды. Меняйте ключ только при плановой миграции, которая
повторно шифрует записи перед удалением старого ключа.

### Экспорт телеметрии OTLP

Экспорт OTLP разрешен через `GPTADMIN_OTLP_ENDPOINT`. Внешние конечные точки
необходимо использовать HTTPS; HTTP разрешен только для сборщиков обратной связи.
Hub экспортирует только конверты структурированных событий из разрешенного списка и ограниченные
корреляционные поля. Аргументы, команды, учетные данные, URL-адреса, содержимое файлов и
необработанные полезные нагрузки исключены. Очередь ограничена, и ошибки экспорта
отказоустойчивость для исходного запроса плоскости управления.

## Режим одобрения

Для критических операций (удаление файлов, изменение конфигурации сети) хаб
поддерживает **режим одобрения**: ИИ предлагает действие, хаб запрашивает
подтверждение человеком перед выполнением. Включите отдельный агент в `/admin` → Безопасность.

## Режим шлюза для серверов MCP

Когда GPTAdmin используется в качестве безопасного прокси-сервера/ретранслятора, внешние клиенты должны подключаться к GPTAdmin, а не напрямую к частным stdio или серверам MCP, работающим только в локальной сети. Предпочитайте URL-адреса для каждого сервера, когда клиенту нужна только одна возможность:

```text
/server/{slug}/mcp
/server/{slug}/actions/openapi.yaml
```

Это сохраняет конфиденциальность восходящего сервера MCP, в то время как GPTAdmin применяет HTTPS, аутентификацию носителя/OAuth, ведение журнала аудита, маршрутизацию и обработку очереди. Используйте полную поверхность `/server/hub/mcp` только для доверенных клиентов, которым необходимы возможности межсерверной ретрансляции/администрирования.

## Контрольный список производственного упрочнения

- [ ] Новая настройка пользовательского GPT использует канал OAuth или управляемый токен MCP с ограниченной областью действия; новый `CTL_TOKEN` не создается
- [ ] Установлен `OAUTH_CLIENT_SECRET` (для `/mcp`)
- [ ] `ADMIN_PASSWORD` сильный
- [ ] Хаб находится за HTTPS (через туннель Cloudflare/FRP или nginx + Certbot)
- [ ] Установлен список разрешенных IP-адресов агентов (только концентратор может связаться с агентами)
- [ ] Брандмауэр: общедоступен только порт концентратора (25900); порт агента (25901) является внутренним
- [ ] Режим одобрения включен для критических операций.
- [ ] Журналы чередуются (`logrotate` или `journalctl --vacuum-time`)
- [ ] Резервные копии настроены (`file_backup` TTL)
