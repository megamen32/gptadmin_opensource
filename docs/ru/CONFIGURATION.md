# Конфигурация

Полная ссылка на переменные среды, модель аутентификации и настройку OAuth.

## Переменные среды концентратора (`go-hub/`)

### Аутентификация

| Вар | Требуется | По умолчанию | Цель |
|-----|----------|---------|---------|
| `ADMIN_PASSWORD` | **да** | — | Пароль для HTML-формы `/oauth/authorize` и сеанса администратора. |
| `CTL_TOKEN` | только существующие установки | — | Устаревший носитель совместимости; не создавайте и не копируйте его. Он остается действительным до тех пор, пока его владелец явно не повернет или не удалит его. |
| `OAUTH_CLIENT_SECRET` | для `/mcp` | — | Подписывает токены носителя OAuth. Создайте с помощью `openssl rand -hex 32`. |
| `PUBLIC_ORIGIN` | рекомендуется | — | Общедоступный базовый URL-адрес (например, `https://your-hub.bezrabotnyi.com`). Используется в OAuth + OpenAPI. |
| `MCP_RESOURCE` | рекомендуется | `$PUBLIC_ORIGIN` | Идентификатор ресурса MCP. |
| `GPTADMIN_RELAX_AUTH_CHECKS` | только аварийный режим | `0` | Установите `1` только на время восстановления ingress/auth-state. Сохраняет проверку подписи/ключа, но временно пропускает claims/срок действия токена и PKCE; после восстановления вернуть `0`. |
| `GPTADMIN_AUTH_RATE_LIMIT` | необязательный | `60` на клиента в минуту | Максимальное количество неудачных попыток аутентификации администратора/контроля/MCP от одного клиента до временного ответа `429`. Успешная аутентификация не расходует бюджет. |

### Сеть

| Вар | По умолчанию | Цель |
|-----|---------|---------|
| `HUB_PORT` | 25900 | Слушать порт |
| `HUB_HOST` | `127.0.0.1` | Слушай хозяина; общедоступные развертывания должны явно устанавливать граничный хост на уровне туннеля/HAOS. `HUB_BIND` остается псевдонимом совместимости установщика. |
| `CORS_ORIGINS` | `*` | Разрешенные источники CORS (через запятую) |

|-----|---------|---------|

| `GPTADMIN_VIRTUAL_MCP_STATE_FILE` | `$GPTADMIN_CONFIG_DIR/virtual_mcps_state.json` | Постоянное состояние включения/выключения для `network-proxy` и `webhooks`; если файл отсутствует, оба остаются выключенными. |
| `GPTADMIN_WEBHOOK_CONFIG_FILE` | `$GPTADMIN_CONFIG_DIR/webhooks.json` | Определения маршрутов универсального веб-перехватчика, принадлежащие оператору. |
| `GPTADMIN_WEBHOOK_STATE_FILE` | `$GPTADMIN_CONFIG_DIR/webhook_state.json` | Надежные веб-перехватчики и ключи воспроизведения; написано в режиме `0600`. |

### Инструкции по запуску MCP

GPTAdmin предоставляет общие рекомендации по системному администрированию в MCP `initialize`
результат. Чтобы постоянно настраивать его, создайте
`$GPTADMIN_CONFIG_DIR/startup_instructions.md` (обычно
`$GPTADMIN_ROOT/config/startup_instructions.md`). Файл должен быть обычным файлом
не более 16 КиБ; нечитаемые, пустые или слишком большие файлы безопасно возвращаются в
встроенное общее руководство. `GPTADMIN_STARTUP_INSTRUCTIONS` переопределяет файл
когда он непустой и не превышает 16 КиБ.

Тот же контент доступен клиентам, игнорирующим `initialize.instructions`.
через MCP `resources/read` по адресу `gptadmin://startup-instructions`. Стартап
инструкции являются оперативным руководством, **не** границей безопасности: настроено
разрешения и утверждения по-прежнему контролируют доступ и выполнение.

Наборы инструкций именованных профилей управляются через аутентифицированный концентратор.
конечные точки `GET /admin/api/instruction-sets` и
`GET|PUT|DELETE /admin/api/instruction-sets/{id}`. `PUT` требует `If-Match`
(`*` для создания); набор не может быть удален, пока ссылается на профиль доступа
это. Выбранный набор профилей возвращается на следующем MCP `initialize` и
чтение ресурса запуска без перезапуска Hub.Управляйте файлом, не допуская случайного раскрытия его содержимого:

```bash
gptadmin instructions path
gptadmin instructions set-file /secure/path/sysadmin_startup.md
gptadmin hub restart
gptadmin instructions show  # explicitly prints the potentially sensitive content
```

`set-file` принимает файлы UTF-8 размером до 16 КиБ, устанавливается атомарно в режиме `0600`,
и печатает только путь назначения плюс подсказку о перезапуске. Интерфейс командной строки использует
выбранная область установки: `~/.config/gptadmin` для установки `--user` и
`/etc/gptadmin` для `--system` устанавливается, если только `GPTADMIN_CONFIG_DIR` не переопределяет его.

## Модель аутентификации

У GPT‑Админ есть **три** механизма аутентификации — они разные, не путайте их.

### 1. Устаревшая версия `CTL_TOKEN` (только временная совместимость)

- Используется для: `/admin`, `/admin/api/*`, `/servers`, `/tasks/*`, конечных точек артефакта.
- Заголовок: `Authorization: Bearer <CTL_TOKEN>` (принимается только для существующего
  учетные данные совместимости, пока их владелец явно не поменяет или не удалит их)
- Это токен «администратора». Его используют веб-панель и пользовательские действия GPT.

### 2. Носитель OAuth (для `/mcp`)

- Используется для: `/mcp` (удаленный SSE MCP)
- `/mcp` обычно использует токен носителя OAuth, который подписывает концентратор.
  `OAUTH_CLIENT_SECRET`. Устаревший существующий носитель совместимости остается.
  принимается только до тех пор, пока его владелец явно не повернет или не удалит его.
— Клиенты MCP (Claude Desktop, Codex) получают этот токен через поток OAuth.

### 3. `ADMIN_PASSWORD` (форма)

– Используется для: формы HTML в `/oauth/authorize` внутри потока OAuth.
— Это то, что человек вводит для авторизации клиента OAuth.

### 4. `SHELLMCP_TOKEN` (агент → хаб)

- Используется для: `POST /heartbeat` (регистрация агента)
— У каждого агента есть свой `SHELLMCP_TOKEN` — хаб проверяет его по контрольному сигналу.
- Это также учетные данные для аутентифицированного опроса очереди. Клиент, который
  не может пройти аутентификацию в Hub, не должно быть одобрено автоматически: работа в очереди может
  содержат конфиденциальные аргументы и результаты команд, поэтому выдающий себя за клиента
  должен быть отклонен до того, как он получит задания.
- Обновления на месте сохраняют эти учетные данные, и служба всегда использует
  канонический `gptadmin.env`. Явное вращение токенов — это отдельная операция;
  установка нового двоичного файла или перезапуск службы не должны его ротировать.
- Новый идентификатор устройства указывается как `awaiting_approval`, а не `offline`.
  Просмотрите его с помощью инструмента Hub MCP `pending` и одобрите ровно один возвращенный файл.
  `server_id` с `approve_pending_server`; одобрение не повторяется для каждого
  опроса или после обычного бинарного обновления.

## Миграция устаревшего носителя

`CTL_TOKEN` — это устаревшие учетные данные совместимости, которые не поддерживаются.
путь. Новые настройки и обновления никогда не создают и не распечатывают их. Существующие учетные данные
остается действительным до тех пор, пока его владелец явно не повернет или не удалит его; нормальные клиенты
следует использовать поток авторизации OAuth AdminPassword или JWT MCP с ограниченной областью действия.
Учетные данные агента ShellMCP являются отдельными и не подпадают под действие этого правила.

## ОАут

В хабе реализованы конечные точки OAuth, совместимые с потоком OAuth OpenAI SDK.

### Конечные точки

| Конечная точка | Метод | Цель |
|----------|--------|---------|
| `/oauth/authorize` | ПОЛУЧИТЬ/ОТПРАВИТЬ | Конечная точка авторизации (показывает форму `ADMIN_PASSWORD`) |
| `/oauth/token` | ПОСТ | Конечная точка токена (учетные данные клиента/код авторизации) |
| `/.well-known/oauth-authorization-server` | ПОЛУЧИТЬ | Метаданные сервера OAuth |

### Настройка

1. Установите `OAUTH_CLIENT_SECRET` на концентраторе (сгенерируйте с помощью `openssl rand -hex 32`)
2. Установите `ADMIN_PASSWORD` (это то, что пользователи вводят в форме авторизации)
3. Установите `PUBLIC_ORIGIN` в качестве URL-адреса общедоступного хаба.
4. Клиенты MCP будут обнаруживать конечные точки OAuth через `/.well-known/...`.

### Жизненный цикл соединенияХаб выдает ответы по протоколу OAuth, в то время как данный клиент MCP или его
коннектор может владеть сохраненным браузером/сеансом и состоянием обновления. Авторизованный
клиент должен иметь возможность обновлять или восстанавливать свой сеанс через поддерживаемый
перезапустить границу. Не пытайтесь обойти сбой обновления на стороне клиента, раскрывая
или копирование внутренних учетных данных. Изменения этой границы требуют
регрессия долговечности авторизации и принятие живого клиента, определенные в
[Контракт на управление интеграцией](./INTEGRATION_CONTROL_CONTRACT.md#authorization-durability).
JWT доступа OAuth остаются недолговечными; непрозрачные учетные данные обновления, выданные Hub
имеет срок службы пять календарных лет и меняется по мере использования. Новые управляемые носители MCP
без явного указания `ttl_days` по умолчанию — пять лет. Существующие подписанные JWT
сохраняют первоначальный срок действия и не заменяются автоматически при установке или обновлении.

### Где установить пароль

На веб-панели: `/admin` → **Безопасность** → установите `ADMIN_PASSWORD` и сгенерируйте
`OAUTH_CLIENT_SECRET`. Или установите их как переменные окружения при запуске хаба.

## Пример `.env`

```bash
# Generate strong values:
# Do not generate CTL_TOKEN on new installations; configure AdminPassword/OAuth instead.
# OAUTH_CLIENT_SECRET=$(openssl rand -hex 32)

ADMIN_PASSWORD=choose-a-password
OAUTH_CLIENT_SECRET=internal-signing-secret
ADMIN_PASSWORD=choose-a-strong-password
OAUTH_CLIENT_SECRET=$(openssl rand -hex 32)
PUBLIC_ORIGIN=https://your-hub.example.com
MCP_RESOURCE=https://your-hub.example.com
```
