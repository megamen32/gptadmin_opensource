# Резервные копии файлов, управляемые GPTAdmin

`file_backup` — предпочтительный инструмент агента оболочки для резервного копирования перед редактированием файлов.
Он заменяет специальные файлы `cp file file.bak.$date`, которые остаются разбросанными по диску.

Инструмент доступен каждому виртуальному агенту `shell:*` через хаб:

- `action=backup` копирует файл или упаковывает каталог в управляемый объект резервного копирования.
- `action=list` перечисляет известные резервные копии в корне управляемой резервной копии.
- `action=cleanup` удаляет резервные копии с истекшим сроком действия или резервные копии старше `max_age_days`.
- `action=restore` восстанавливает резервную копию `backup_id`.

Хранилище по умолчанию на целевом хосте:

```text
~/.gptadmin/file-backups/
```

Срок хранения новых резервных копий по умолчанию — `ttl_days=30`. Используйте `ttl_days=0` только для резервных копий, срок действия которых не должен истекать автоматически.

Каждая резервная копия имеет `meta.json` и `manifest.jsonl`, предназначенный только для добавления. Программа очистки сканирует только этот управляемый корень резервной копии, а не всю файловую систему.

Примеры:

```json
{"action":"backup","path":"/home/roomhacker/gptadmin/go-hub/internal/hub/server.go","ttl_days":30,"label":"before-admin-api-change"}
```

```json
{"action":"list","limit":20}
```

```json
{"action":"cleanup"}
```

```json
{"action":"restore","backup_id":"20260624_144633_host_abcd1234_label","overwrite":true}
```

Для привилегированных файлов передайте `use_sudo=true`; целевой хост должен разрешить неинтерактивный `sudo -n`.
